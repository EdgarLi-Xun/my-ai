# 暂不引入微信集成

我们评估过把微信作为 MyAi 的聊天通道，**决定暂不开发**（2026-07-24）。调研发现最自然的解读——"在企业微信群里 @ 机器人"——官方自建应用回调 API 并不支持；唯一能读群消息的官方路径需要付费开通"会话内容存档"资质；公众号方案则是单聊、没有群聊能力。我们选择优先合规与个人开发者可落地，而不是拉宽功能面。

## 考虑过的选项

- **A. 企业微信自建应用（群聊 @ 机器人）** — 拒绝。官方回调无法接收群里的 @ 消息；只有"会话内容存档"才能读群。
- **A.1 企业微信自建应用（单聊）** — 可行、官方，但失去"群里 @ 机器人"的能力。暂缓，未拒绝。
- **A.2 会话内容存档 SDK** — 官方、可读群聊历史，需付费企业资质。当前维护者画像下不可行。
- **A.3 第三方 SCRM 中转（语鹦企服、微丰等）** — 能实现群里 @ 机器人，但引入第三方厂商、付费方案、外部信任边界。未采纳。
- **B. 公众号（订阅号/服务号）** — 官方，但没有群聊；等同于把场景换成"单用户 AI 客服"。与原始"群里 @ 机器人"诉求不一致。
- **C. 个人微信 hook（web/iPad 协议）** — 非官方、违反微信 ToS。出于合规理由拒绝（与 MyAi 当前的安全边界相冲突）。

## 后果

- MyAi 仍是单渠道应用：仅 Web 前端与它对话。
- `User` 领域模型不变：不引入微信 `openId` 映射、没有群身份、没有按群维度的会话。
- 未来若重新评估，必须再次核实企业微信 API 表面——该方向 2026 年持续演进（如"大圆" Agent 内部测试）。本决策以 2026-07-24 验证的事实为锚。
